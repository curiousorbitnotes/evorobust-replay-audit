Impossible Code, Barely Changed Score

A Replay Study of Judge-Based Evaluation

We re-ran two trained AI coding models. Most of the code they now write is no longer valid Python. The AI judge that grades the code still gave almost the same score: it fell by about three percentage points.

The problem

Training a language model with reinforcement learning needs a scorer that says whether an answer is right. For code, the dependable scorer runs the program against tests. That is slow and needs a sandbox, so many studies ask a large language model to read the code and judge it instead. This page reports what that substitution cost inside one real evaluation.

What happened

A finished study had trained Qwen-2.5-7B-Instruct with GRPO and saved the code its checkpoints wrote for 421 HumanEval and MBPP problems (32 samples each). Later we downloaded the released checkpoints and asked the same questions again (128 samples each), on different hardware. The base model's syntax-failure rate stayed similar. The trained checkpoints instead produced mostly invalid Python, almost always because of one extra closing bracket. The judge-based scores changed only slightly.

Which model does what?

The base, CE-trained and SLJ-trained checkpoints are versions of Qwen-2.5-7B-Instruct that write code. CE-trained received rewards from execution tests, while SLJ-trained received rewards from an AI judge. The separate strong judge is Qwen-2.5-72B-Instruct, and the weaker judge is Qwen-2.5-7B-Instruct. The parser checks code syntax, while execution runs tests.

What the paper proposes

Report the syntax-check rate beside every judge score.

The share of outputs that parse. It needs no tests and no sandbox, and it would have flagged this change on the day it happened. Applied as a gate on the judge, it lowers judge-based Pass@1 by 0.19 percentage points on the healthy base run and by 40.51 percentage points on the damaged SLJ-trained run. Parsing does not show that code runs or is correct.

import ast

# extracted_code: the last code block of the response
def gated(judge_says_yes, extracted_code):
    if not extracted_code.strip():
        return False
    try:
        ast.parse(extracted_code)
    except Exception:
        return False
    return judge_says_yes

A judge's accuracy and its sensitivity to change are different properties.

A high judge-based score can sit next to a model whose outputs have stopped being programs.

Why it matters for self-evolving search

Program-search systems such as FunSearch and AlphaEvolve score each candidate by running it through an automated evaluator. Self-rewarding training scores candidates with a model's own judgment. A judge that cannot tell broken output from working output can steer such a search toward whatever it accepts.

The judge likes valid code but does not require it

Take the second-run answers of the SLJ-trained model. The strong judge approved 83.35% of the answers that were valid Python. It also approved 60.56% of the answers that were not. Because about two thirds of the answers were broken, 59.49% of everything the judge approved was code that cannot run. The base model wrote only 216 broken answers. The judge approved 47.69% of them, but they make up just 0.23% of its approvals.

Further checks in the paper

Is it cut-off answers or a bug in extraction?

Neither explains it. In the SLJ-trained model, 98.6% of the errors are an extra or mismatched closing bracket, and only one looks like an answer cut off part-way. Reading any code block instead of the last one barely changes the share of valid answers (33.10% against 33.12%).

What if only some answers are broken?

We added one extra bracket to 10% to 60% of the base model's answers. The share of valid answers fell from 99.5% to between 89.3% and 39.9%, yet the judge's score moved by at most 0.24 percentage points.

Does a smaller judge do better?

Yes, it notices more. The weak 7B judge approves less broken code (28.0% and 30.4% of it), and its score falls by about 16 percentage points between runs. Both judges come from the same model family, so this does not tell us how other judges behave.

Is the gap real or noise?

At 128 attempts, the base-minus-SLJ-trained judge gap is 0.71 percentage points, with a 95% interval of [−1.19, 2.61] percentage points. That interval includes zero. The execution gap is 15.91 percentage points, with an interval of [12.11, 19.95] that stays above zero. These compare the models on the same later-run questions.

You are an expert grader. Your job is to decide whether a candidate

Output exactly one character: '1' if the candidate answer is correct,
or '0' if it is incorrect. Do not output anything else — no reasoning,
no punctuation, no whitespace.
